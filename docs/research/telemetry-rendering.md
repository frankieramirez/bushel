## 1. Glyph strategies: block vs braille, and the ASCII fallback

### The field's three-tier ladder

btop is the canonical statement of the trade-off. Its `graph_symbol` config offers three sets — README: *"'braille' offers the highest resolution but might not be included in all fonts. 'block' has half the resolution of braille but uses more common characters. 'tty' uses only 3 different symbols but will work with most fonts and should work in a real TTY"* ([README](https://github.com/aristocratos/btop)). Each set is a 25-entry lookup table encoding **two samples per cell**, each quantized to 5 levels ([src/btop_draw.cpp:89–132](https://github.com/aristocratos/btop/blob/main/src/btop_draw.cpp), indexing at :424):

- **braille**: ` ⢀⢠⢰⢸ / ⡀⣀… / …⣿` — 4 vertical levels per half-cell;
- **block**: quadrant blocks `▖▄▟▌▙█…` — half braille's vertical resolution;
- **tty**: only `░ ▒ █` (U+2591/2592/2588), height encoded as shade density. Note this is CP437/Linux-console-safe, **not pure 7-bit ASCII**.

`force_tty` swaps every graph to the tty set and "other non tty friendly symbols" too (README). Predecessor bpytop had the identical three-way option.

### What everyone else actually ships

Braille is rarer in practice than its reputation suggests:

- **bottom** is the one braille user: it vendors ratatui's chart/canvas and defaults to `Marker::Braille` ([src/canvas/components/time_series/vendored.rs:458](https://github.com/ClementTsang/bottom/blob/main/src/canvas/components/time_series/vendored.rs)), with `--dot_marker` falling back to `•` U+2022 ([src/canvas.rs:66–71](https://github.com/ClementTsang/bottom/blob/main/src/canvas.rs); [CLI docs](https://bottom.pages.dev/nightly/configuration/command-line-options/)). Its other degradation path, `--basic`, hides graphs entirely for an htop-like numeric look ([src/options/args.rs:106–112](https://github.com/ClementTsang/bottom/blob/main/src/options/args.rs)).
- **zenith** uses stock ratatui `Sparkline` with the default eighth-block set `▁▂▃▄▅▆▇█` everywhere and has no fallback of any kind ([src/renderer/network.rs:46,70](https://github.com/bvaisvil/zenith/blob/master/src/renderer/network.rs); [src/renderer/cpu.rs:152,166](https://github.com/bvaisvil/zenith/blob/master/src/renderer/cpu.rs)).
- **k9s** rolls its own sparkline on the same eighth-block runes `▁…█` — stacked `█` columns with one partial glyph on top ([internal/tchart/sparkline.go:14](https://github.com/derailed/k9s/blob/master/internal/tchart/sparkline.go)). No braille anywhere in k9s.
- **ctop** (termui): compact rows use a **background-color gauge** — spaces with a colored `Bg`, fully ASCII-safe ([gizak/termui gauge.go @ 8d4faad](https://github.com/gizak/termui/blob/8d4faad06196/gauge.go)); the expanded view uses `▁…█` sparklines for NET/IO ([termui sparkline.go:12](https://github.com/gizak/termui/blob/8d4faad06196/sparkline.go)) and a `•` dot-mode line chart for CPU — explicitly opting out of termui's default braille mode (`cpu.Mode = "dot"`, [cwidgets/single/cpu.go](https://github.com/bcicen/ctop/blob/master/cwidgets/single/cpu.go)).
- **oxker** uses ratatui `Chart` with `Marker::Dot` + `GraphType::Line` for CPU, memory, and bandwidth — again not braille ([src/ui/draw_blocks/chart_cpu_mem.rs](https://github.com/mrjackwills/oxker/blob/main/src/ui/draw_blocks/chart_cpu_mem.rs), [chart_bandwidth.rs](https://github.com/mrjackwills/oxker/blob/main/src/ui/draw_blocks/chart_bandwidth.rs)).
- **lazydocker** plots with jesseduffield/asciigraph, which despite the name draws box-drawing lines `╭─╮╰│┤┼` ([asciigraph.go:113–141](https://github.com/jesseduffield/asciigraph/blob/master/asciigraph.go)) — not ASCII either.

So the container-manager cohort (ctop, oxker, k9s, lazydocker) ships **zero braille**; the vocabulary in that space is block sparks (`▁…█`), dot-line charts (`•`), and color-only gauges. Braille belongs to the monitoring products (btop, bottom) where 2×4 sub-cell resolution earns its font risk.

### Ratatui's toolkit for each tier

- **Sparkline** (0.30): default `bar_set` is `symbols::bar::NINE_LEVELS` — `▁▂▃▄▅▆▇█` + space, exactly U+2581–2588 ([ratatui-core/src/symbols/bar.rs:1–27](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/ratatui-core/src/symbols/bar.rs)); `THREE_LEVELS` degrades to `▄█` + space. Crucially, `symbols::bar::Set` is a public struct of plain `&'a str` fields (`full`, `seven_eighths`, … `empty`; bar.rs:10–21) and `Sparkline::bar_set()` is a `const fn` ([ratatui-widgets/src/sparkline.rs:232–236](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/ratatui-widgets/src/sparkline.rs)) — so a **custom pure-ASCII set is a one-const change**, e.g. `full:"#", …, half:"=", one_quarter:":", one_eighth:".", empty:" "`. Ratatui's own demo app toggles `NINE_LEVELS` vs `THREE_LEVELS` on an `enhanced_graphics` flag ([examples/apps/demo/src/ui.rs:70–79](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/examples/apps/demo/src/ui.rs)) — the exact shape of bushel's `--ascii` switch.
- **Braille** lives in `Canvas`/`Chart` via `Marker::Braille` (`PatternGrid::<2,4>` in 0.30, [ratatui-widgets/src/canvas.rs:578–592](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/ratatui-widgets/src/canvas.rs)); the source itself warns "`Marker::Braille` requires a font that supports Unicode Braille Patterns" ([chart.rs:374–378](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/ratatui-widgets/src/chart.rs)), and the [FAQ](https://ratatui.rs/faq/) notes unsupported glyphs render as `□`/`�`. Braille cells also take **one foreground color per cell** — "There is no way to set the individual color of each pseudo-pixel" (canvas.rs:126–139) — so overlapping series color-collide; only `HalfBlockGrid` gets two colors per cell via fg/bg (canvas.rs:304–315).
- **Gauge/LineGauge**: `Gauge::use_unicode()` fills the boundary cell with left-eighth blocks `▏▎▍▌▋▊▉█` via a hardcoded mapping (no public `gauge::Set` in 0.30; [gauge.rs:219–229](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/ratatui-widgets/src/gauge.rs)) — and even non-unicode Gauge still paints `█` cells, so it's never truly ASCII. **LineGauge** is: one row, `filled_symbol`/`unfilled_symbol` are arbitrary strings (default `─`; `line_set()` is deprecated in 0.30, gauge.rs:329–334), so `.filled_symbol("=").unfilled_symbol("-")` is a complete ASCII story. Both panic on out-of-range ratios — clamp telemetry before passing.

**Verdict for bushel**: eighth-block `Sparkline` is the field-proven middle tier (zenith, k9s, ctop-net all use exactly these glyphs), Ratatui makes the ASCII fallback a const swap, and braille buys nothing at strip height while costing font compatibility and per-cell color freedom.

## 2. Rates from cumulative counters, next to instantaneous values

bushel already derives CPU% from Apple's cumulative `cpuUsageUsec` across consecutive samples (`src/engine/state.rs` `apply_stats`); net rx/tx and disk r/w are the same shape. Conventions across the cohort:

**Derivation hygiene**
- **Skip or zero the first sample** — a delta needs two points. bottom explicitly zeroes it: `NetworkHarvest::first_run_cleanup()` sets `rx = tx = 0` on the first collection ([src/collection/network.rs:19–24](https://github.com/ClementTsang/bottom/blob/main/src/collection/network.rs)); ctop's `DiffHist` swallows sample #1 (`if h.lastVal >= 0 { … }`, [cwidgets/single/hist.go](https://github.com/bcicen/ctop/blob/master/cwidgets/single/hist.go)). btop instead relies on the first delta dividing by a huge elapsed time (≈0) — the sloppier pattern.
- **Divide by measured elapsed time**, not nominal cadence: btop uses real elapsed ms and handles counter rollover by accumulating when `val < last` ([linux/btop_collect.cpp ~:2975–2990](https://github.com/aristocratos/btop/blob/main/src/linux/btop_collect.cpp)); bottom uses `Instant` elapsed with a divide-by-zero guard ([collection/network/sysinfo.rs:37–46](https://github.com/ClementTsang/bottom/blob/main/src/collection/network/sysinfo.rs)). zenith divides by the *configured* tick instead ([src/renderer/network.rs:31–33](https://github.com/bvaisvil/zenith/blob/master/src/renderer/network.rs)) — wrong when polls jitter.

**Presentation**
- **Direction glyph + humanized rate + `/s`**, distinct color per direction, is universal: btop `▲`/`▼` with download graphed inverted in the top half of the net box ([btop_draw.cpp:1579](https://github.com/aristocratos/btop/blob/main/src/btop_draw.cpp)); zenith `↑ [rate/s] PEAK [max/s]` / `↓ …` in block titles, upload LightYellow over download LightMagenta ([network.rs:46–78](https://github.com/bvaisvil/zenith/blob/master/src/renderer/network.rs)); oxker `↓ rx ↑ tx` columns and `" rx: 566.00 kb/s tx: 56.60 kb/s "` in the chart title; ctop expanded titles `RX [12k/s]` ([cwidgets/single/net.go](https://github.com/bcicen/ctop/blob/master/cwidgets/single/net.go)).
- **Units**: btop defaults to binary bytes (`KiB/s`) with a bits-in-parentheses extra and `base_10_*` toggles ([btop_tools.cpp:419](https://github.com/aristocratos/btop/blob/main/src/btop_tools.cpp) `floating_humanizer`; README); bottom stores bits internally ("All units in bits", [collection/network.rs:7](https://github.com/ClementTsang/bottom/blob/main/src/collection/network.rs)) and defaults to SI bits/s with `--network_use_bytes`/`--network_use_binary_prefix` toggles; ctop uses 0-precision short binary (`12K`, `3M`); zenith binary bytes. For a container manager (not a network tool), bytes with binary prefixes and no toggle is the ctop/zenith/lazydocker norm.
- **Rate + context value**: btop shows current + `Top:` (peak) + `Total:` (cumulative) when space allows; bottom's legend is `RX: {rate} All: {total}` ([network_graph.rs:163–181](https://github.com/ClementTsang/bottom/blob/main/src/canvas/widgets/network_graph.rs)); zenith shows current + PEAK. The compact-strip version of this is one context number, not three.
- **Numbers for net/disk, graphs for cpu/mem** is the container-cohort pattern: ctop rows show NET/IO as cumulative text; k9s has no per-row net at all; lazydocker prints cumulative traffic text and derives rates only for CPU%/MEM% ([pkg/commands/container_stats.go](https://github.com/jesseduffield/lazydocker/blob/master/pkg/commands/container_stats.go)); oxker graphs rx/tx but shows disk not at all. Only ctop's expanded view graphs all four.
- **Scaling when rates are graphed**: auto-scale y to the visible max — bottom uses 1.5× current max with a nonzero floor ([network_graph.rs:384–443](https://github.com/ClementTsang/bottom/blob/main/src/canvas/widgets/network_graph.rs)), btop ratchets up/down with a 10 KiB floor and `net_sync` to share one scale across directions (README), zenith/oxker use window max (oxker shares one scale across rx and tx: y-bound = `max(max_rx, max_tx)`, [chart_bandwidth.rs](https://github.com/mrjackwills/oxker/blob/main/src/ui/draw_blocks/chart_bandwidth.rs)). Log scale exists only as bottom's `--network_use_log` option; btop has none. Instantaneous percentages get a fixed 0–100 scale, never auto.

## 3. Glanceable strip vs monitoring product: the visual vocabulary

The cohort splits cleanly into two registers, and the distinguishing features are consistent:

- **ctop** is the archetype two-register design: the *row* register is one cell — a background-color gauge with the value text overlaid (`NN%`, `used/limit`) and plain `rx / tx` text, no history, no axes, severity color (green ≤70 / yellow ≤90 / red) doing the graph's job ([cwidgets/compact/gauge.go](https://github.com/bcicen/ctop/blob/master/cwidgets/compact/gauge.go), text.go). History exists only in the opt-in expanded view (`o`), which is a different screen entirely (CPU chart height 12, MEM 13, NET 6, IO 6, in a fixed 65-col column; [cwidgets/single/main.go](https://github.com/bcicen/ctop/blob/master/cwidgets/single/main.go)).
- **k9s** abstains entirely in-table — right-aligned numeric `CPU`/`MEM`/`%CPU/L`… columns ([internal/render/pod.go:63–70](https://github.com/derailed/k9s/blob/master/internal/render/pod.go)) — and quarantines all graphing in the separate `:pulse` dashboard, which is where the axes and legends live.
- **oxker** is the closest model to bushel's plan: numeric list columns plus an always-visible chart strip (cpu | memory | bandwidth) at the bottom of the frame, ~7 rows in its snapshot tests ([draw_blocks/snapshots/…whole_layout.snap](https://github.com/mrjackwills/oxker/blob/main/src/ui/draw_blocks/snapshots/)). What keeps it glanceable: **no x-axis labels** (fixed 60-sample window), **y-axis reduced to a single label = the historical max**, **current value promoted into the block title** (`" cpu 03.00% "`), **no legend** (color + title carry identity).
- **lazydocker**'s Stats tab is the cautionary full-product register: two 10-row asciigraph plots with numeric y-axes, captions, then a raw YAML stats dump ([pkg/gui/presentation/container_stats.go](https://github.com/jesseduffield/lazydocker/blob/master/pkg/gui/presentation/container_stats.go) `plotGraph`, `RenderStats`). Its one strip-relevant number: default history window `stats.maxDuration` = **5 minutes** ([pkg/config/app_config.go:277–284](https://github.com/jesseduffield/lazydocker/blob/master/pkg/config/app_config.go)) — exactly bushel's planned window.
- The monitoring products confirm from the other side: bottom's charts have real time axes (two labels: window size left, "0s" right; [time_series/base.rs:115–129](https://github.com/ClementTsang/bottom/blob/main/src/canvas/components/time_series/base.rs)) and 10-minute retention; btop, interestingly, has **no axes at all** even as a full dashboard — values are text overlaid on the graph — showing that axis-lessness alone isn't what makes a strip; bounded height and value-first text are.

**Distilled grammar of "seasoning, not product"**: (1) no x-axis; (2) at most one y reference, the max, rendered as text; (3) fixed short window, not configurable; (4) current value as text *first*, adjacent to or overlaid on the glyphs, with the graph as context; (5) no legend — label + color carry identity; (6) severity/direction color; (7) history lives in the strip only — a taller view is a different register and bushel deliberately doesn't have one.

Useful micro-idioms: ctop draws a 5%-wide low-contrast stub bar even when the value is <5% so the gauge reads as structure, and shows `-` for no-data; oxker renders the empty chart frame with `00.00%` in the title rather than hiding the strip; k9s right-aligns partial history against the right edge so the sparkline **grows leftward from newest-pinned-right** ([sparkline.go](https://github.com/derailed/k9s/blob/master/internal/tchart/sparkline.go) `cutSet`, `cX = rect.Max.X - len(s.series) - 1`) — much nicer in the first minutes than ctop's zero-prefilled flatline.

## 4. Ratatui-specific traps (0.30)

All references are to tag `ratatui-v0.30.0`.

- **Sparkline truncates the tail, not the head.** The render loop is `for (i, item) in self.data.iter().take(min(width, len))` — it always draws `data[0..width]`, in *both* `RenderDirection`s ([sparkline.rs:364–371](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/ratatui-widgets/src/sparkline.rs)). Push newest samples onto the end of a Vec and a narrow strip shows the **oldest** N samples. Either slice the tail yourself (`&buf[buf.len().saturating_sub(width)..]` with `LeftToRight`) or store newest-first and use `RightToLeft` — the latter also gives the k9s newest-pinned-right, grow-leftward behavior for free.
- **0.30 API**: `Sparkline` data is `Vec<SparklineBar>` where `SparklineBar { value: Option<u64>, style: Option<Style> }` (sparkline.rs:252–262); `From` impls cover `u64`/`Option<u64>` so `.data(vec![Some(1), None, …])` works. A `None` renders `absent_value_symbol` (default space) full-height with `absent_value_style` — a clean "missed poll" gap. Per-bar `style` allows threshold-coloring spikes.
- **Scaling**: `.max()` unset auto-scales to the dataset max (fallback 1) (sparkline.rs:359–361). Set `.max(100)` for CPU%/mem% or the strip will show noise at full height when idle; leave auto (or ratchet your own) for rates.
- **Chart is overkill at strip height**: it demands f64 datasets with hand-maintained x counters and explicit `Axis::bounds` (no auto-scaling), and axis labels/legend eat rows from a 3–4-row strip ([chart.rs:69–76, 770–812](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/ratatui-widgets/src/chart.rs)); its braille resolution advantage (4 sub-rows/cell vs Sparkline's 8 levels/cell) is marginal, and it has no ASCII story beyond `Marker::Dot`.
- **Gauge panics** on ratio outside 0.0–1.0 / percent > 100 (`assert!`, gauge.rs) — clamp derived values (bushel already caps CPU% at 999, which would panic a Gauge).
- **Resize is free but frame-gated**: `Terminal::draw` calls `autoresize()` every frame; a size change resizes both buffers and forces a **full clear + repaint** ([ratatui-core/src/terminal/terminal.rs:279–321, 453–455](https://github.com/ratatui/ratatui/blob/ratatui-v0.30.0/ratatui-core/src/terminal/terminal.rs)). At a 1 s tick, redraw immediately on `Event::Resize` (bushel's event loop should already treat resize as a draw trigger) or the cleared screen sits blank up to a second.
- **Per-frame cost is a non-issue at 1 s cadence**: Sparkline render is O(width × height) cell writes with no allocation; the only allocation is `.data()` collecting a Vec of ≤ width items per sparkline per frame (sparkline.rs:209–216, 354–421). Buffer diffing means an unchanged frame emits nothing ([FAQ](https://ratatui.rs/faq/): double buffer, diffs only). The FAQ's real rule: exactly one `terminal.draw()` call per loop iteration, all widgets in the one closure.
- **Fonts**: braille and octant glyphs are the fragile ones; U+2581–2588 blocks are single-width and widely supported but can render with visible gaps/uneven eighths in some fonts — which is what `THREE_LEVELS` and custom sets are for. New in 0.30, `Marker::Quadrant`/`Sextant`/`Octant` offer denser canvas mosaics with (for quadrants) better font support than braille — irrelevant at strip height but worth knowing.

## Implications for bushel's telemetry strip

Concrete inputs for the prototype (#17):

1. **Glyphs: ratatui `Sparkline` with the default `NINE_LEVELS` eighth-blocks; no braille, no Chart, no Canvas.** This matches what the container cohort actually ships (k9s, ctop, zenith use exactly these runes), keeps one sample per column (5 min @ 1 s = 300 samples ≥ any plausible pane width — the strip will show the most recent `width` seconds, which is honest), and avoids braille's font fragility and one-color-per-cell limit. For any rate *bars* (if used), `LineGauge` with `filled_symbol`/`unfilled_symbol`, not `Gauge` (which is never ASCII-safe and panics on >100%).
2. **`--ascii` fallback: a custom `symbols::bar::Set` const** — e.g. `" .:-=+*#"` ramp with `#` full — swapped in exactly like ratatui's own demo swaps `NINE_LEVELS`/`THREE_LEVELS` on its `enhanced_graphics` flag. `bar_set()` is const-friendly; this is a `Theme`-level decision alongside the existing `● / *` dot substitution in `src/ui/theme.rs`. LineGauge ascii is `.filled_symbol("=").unfilled_symbol("-")`. Do not use btop's `░▒█` tty set as the ascii tier — it's CP437, not ASCII, and bushel's flag promises ASCII.
3. **Feed sparklines newest-first + `RenderDirection::RightToLeft`** (or tail-slice with LeftToRight). This sidesteps the head-truncation trap *and* reproduces k9s's best-in-cohort warm-up behavior: the sparkline grows leftward from the right edge instead of scrolling across a fake zero-flatline. `VecDeque` ring buffer per metric, `push_front`, capped at ~300.
4. **Scale**: `.max(100)` for CPU% (clamped ≤100 for display — the engine's 999 cap would render as noise-flattening; show `>100%` numerically if it happens) and mem as % of limit; auto-max for rate sparklines if rates are graphed, one shared scale per pair (rx/tx together, r/w together — btop's `net_sync`, oxker's shared bandwidth bound) so the two directions are comparable.
5. **Rates: first-difference cumulative counters ÷ measured elapsed time, and swallow the first sample** (render `-`/absent, per bottom's `first_run_cleanup` and ctop's `DiffHist`) — never a bogus first delta. Guard `elapsed == 0` and counter decrease (treat as reset). This generalizes the existing `apply_stats` CPU% derivation to net/disk.
6. **Rate display convention**: direction glyph + humanized binary bytes + `/s`, colored per direction — `↑ 1.2M/s ↓ 340K/s` (`^`/`v` in ascii mode), disk `r`/`w` likewise. Numbers-first: net/disk earn text, cpu/mem earn sparklines (the cohort norm); graph rates only if the prototype shows spare rows. One context value at most (peak-in-window, zenith-style), not btop's rate+top+total stack. No bits, no unit toggles — bushel is a manager, not a network tool.
7. **Strip grammar — what keeps it "seasoning"**: no x-axis, no legend, no borders-per-metric; each metric line reads `label · current value (text, first) · sparkline filling remaining width`, identity by label + color, severity color on the value (ctop's ≤70 green / ≤90 yellow / red is the established scale). At most one reference number per sparkline (the window max, oxker-style) and only if it fits. Empty/no-data state renders the frame with `-` values (ctop) rather than hiding the strip — the strip collapsing is a *height* decision (pane too short), not a data decision.
8. **Ratatui gotchas to design around**: clamp before Gauge-family widgets (panic on >1.0); redraw on `Event::Resize` immediately (resize forces a full clear); one `terminal.draw()` per loop tick; per-frame Sparkline cost at 1 s cadence is negligible (one ≤ width-item Vec per sparkline), so no caching or dirty-tracking machinery is warranted in the prototype.

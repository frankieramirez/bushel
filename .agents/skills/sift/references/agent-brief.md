# Agent brief

A structured comment posted when an issue (or in-scope PR) moves to `ready-for-agent`. The original body is context. This comment is the contract an AFK agent builds from.

For a PR, the brief states what is left to do to the existing diff.

Every brief is posted under the triage disclaimer from the skill spine.

## Write for a later week

The issue may sit for days. Files will move. Describe interfaces, types, and behavior. Name the type or the function signature the agent should look for. File paths and line numbers go stale.

Describe what the system should do. The agent will pick the files.

Every brief has concrete, independently checkable acceptance criteria. State what is out of scope so adjacent work stays off this ticket.

## Template

```markdown
> *This was generated by AI during triage.*

## Agent Brief

**Category:** bug / enhancement
**Summary:** one line

**Current behavior:**
What happens now. For a bug, the break. For an enhancement, the status quo.

**Desired behavior:**
What is true after the work. Include the edge cases that matter.

**Key interfaces:**
- `TypeName`: what changes
- `functionName()`: current return vs wanted return

**Acceptance criteria:**
- [ ] Observable check
- [ ] Observable check

**Out of scope:**
- Adjacent work that stays off this ticket
```

## Ready-for-human

Same template. Add one line under Summary: why a person has to do it (judgment still open, credentials, a design call, a test only a human can run).
